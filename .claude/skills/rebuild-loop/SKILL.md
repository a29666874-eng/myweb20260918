# 研究 → 重建 → 比對 → 修正(閉環重建)

## 參數

開始前先確認三個參數;使用者沒給的就問(用 AskUserQuestion,給 2–4 個選項):

- **目標**:網址、App 名稱、本機路徑或截圖。必須是使用者自己的、或使用者有權檢查的東西。若看起來是第三方產品且沒有說明權限，先問清楚。
- **技術**:例如 React / Vue / 純 HTML+CSS / Rust。
- **N**:最多修正輪數(預設 3)。

## 全程規則

1. **只看外觀與公開行為**:可以截圖、操作頁面、量測尺寸與顏色;**不要**讀取、複製或改寫目標的原始碼(包括 view-source、打包後的 JS/CSS 檔)。
2. **不複製商標、照片或文字**:Logo 用中性佔位圖形，照片用純色或佔位圖，文字用意思相近但重新撰寫的佔位文案。
3. **會真正影響結果的選擇先問**:例如框架/版本、要不要後端、RWD 斷點、資料來源、找不到的字型如何替代。一次提出 2–4 個選項並標出建議項。不影響結果的小事自己決定，並在報告中寫明。
4. **每項結論都標註證據等級**:
   - `[觀察]` 實際截圖或操作看到的
   - `[計算]` 由量測數值推算的(例如像素差異比例、色差 ΔE)
   - `[猜測]` 推論，尚未驗證
   - `[未檢查]` 還沒驗證的項目，要明確列出
5. **每輪結束用 3–5 句話總結還沒解決的問題**。

## 步驟

### 1. 研究 → 寫規格

- 用 Playwright(已預裝:`require('playwright')`)在桌機 1440×900 與手機 390×844 兩種寬度截圖，存到 scratchpad。
- 整理成 `spec.md`(放在新專案根目錄),內容包括:
  - **版面**:區塊結構、格線、間距、對齊方式、斷點行為
  - **顏色與字體**:色碼 token(背景、文字、強調色、邊框)、字級、字重、行高、圓角、陰影
  - **功能清單**:每個互動元件的觸發方式 → 預期結果(導覽、表單驗證、彈窗、動畫、hover/focus 狀態等)
  - **素材替代表**:原本的 logo/照片/文案 → 佔位方式
- 每條規格都加上證據標註。

### 2. 重建

- 依 `spec.md` 用指定技術建立**全新**專案(預設目錄 `rebuild/<目標名稱>/`,若使用者另有指定則照做)。
- 顏色與間距寫成 token / CSS 變數，方便後續調整。
- 確認專案能啟動並正常渲染。

### 3. 比對

- 用相同的視窗尺寸對原版與重建版截圖。
- 如果可以，用像素差異(例如 `pixelmatch` 或 Python PIL)算出差異比例並輸出 diff 圖 → 標 `[計算]`。
- 逐項走過功能清單，實際操作兩邊 → 標 `[觀察]`。
- 產出比對表:

| 項目 | 原版 | 重建版 | 像/不像 | 證據 |
|---|---|---|---|---|

- 最後列出「尚未檢查」清單。

### 4. 修正

- 依比對表優先修正差異最大的項目，再回到步驟 3。
- 最多 **N** 輪。
- **停止條件**:
  - 達到 N 輪;或
  - **連續兩輪沒有進步**(像素差異比例沒有下降，且「不像」項目數也沒有減少)→ 立刻停下來報告，不要繼續硬修。
- 每輪記錄:輪次、改了什麼、差異比例變化、不像項目數變化、3–5 句未解決問題總結。

## 最終報告

1. 每一輪的進步表(輪次 / 差異比例 / 不像項目數)
2. 最終比對表(含證據標註)
3. 尚未檢查與尚未解決的項目
4. 自行決定的小事與理由
5. 截圖與 diff 圖的路徑

完成後 commit 並 push 到目前指定的分支。
